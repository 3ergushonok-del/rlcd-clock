# Часы + погода — Waveshare ESP32-S3-RLCD-4.2

Прошивка на Arduino-ESP32 (PlatformIO) для платы с 4.2″ отражающим экраном
(ST7305, 400×300, монохром).

Плата **спит в глубоком сне и просыпается раз в 3 часа**, чтобы обновить погоду,
либо по нажатию любой кнопки. Экран при этом продолжает показывать картинку —
панель ST7305 держит изображение без обновления.

> Скриншоты в репозиторий не входят: на них видно название города и адрес
> в локальной сети. Снять свои можно через `tools/shot.py`.

## Что показывает

**Главный экран — дата и текущая погода (часов нет):**

```
 СР, 18 ноября                          <город>
 ─────────────────────────────────────────────
   -2°                    ☁
                          снег
   ощущ. -6°
 ─────────────────────────────────────────────
 ветер 4.0 м/с · влажн. 70%
 давл. 1018 гПа · сегодня -2°…-1°
 ─────────────────────────────────────────────
 в доме 25.4° · 40%                 100% ▮▮▮
```

**Экран прогноза (кнопка KEY) — три дня, макс/мин и иконка:**

```
 ПОГОДА НА 3 ДНЯ                        <город>
 ─────────────────────────────────────────────
  СЕГОДНЯ   │   ЗАВТРА   │      ПТ
    18.11   │    19.11   │    20.11
     ☁      │     ☁      │     ☀☁
  -1° / -2° │  0° / -2°  │  0° / -4°
    снег    │  облачно   │  переменно
 ─────────────────────────────────────────────
 макс / мин · KEY — назад     обновлено 14:57
```

- **Погода** — met.no (Норвежский метеоинститут), без API-ключа, раз в 20 минут
- **Дата** — из SNTP + PCF85063 (RTC переживает отключение питания)
- **В доме** — SHTC3 на самой плате
- **Батарея** — ADC, напряжение и проценты
- Экран обновляется только при изменении данных: минутного таймера больше нет

## Управление

| Кнопка | Действие |
|---|---|
| **KEY**, короткое | переключить экран: погода ↔ прогноз на 3 дня (сам вернётся через 2 минуты) |
| **KEY**, долгое (>0.9 с) | обновить погоду немедленно |
| **BOOT**, короткое | экран состояния: Wi-Fi, IP, RSSI, NTP, батарея, SRAM, uptime |
| **BOOT**, долгое | инверсия экрана (тёмная тема), запоминается в NVS |

Любая кнопка также **будит плату из глубокого сна**.

## Энергосбережение

| Параметр | Значение | Где менять |
|---|---|---|
| Интервал автообновления | 3 часа, привязка к 00:05 / 03:05 / 06:05 … | `SLEEP_INTERVAL_S`, `SLEEP_ANCHOR_MIN` |
| Окно после пробуждения по таймеру | 3 мин | `AWAKE_TIMER_MS` |
| Окно после пробуждения кнопкой | 3 мин | `AWAKE_BUTTON_MS` |
| Окно после включения/прошивки | 3 мин | `AWAKE_COLD_MS` |

Как это работает:

- Просыпаясь по таймеру, плата берёт время из PCF85063, поднимает Wi-Fi,
  синхронизирует NTP, забирает погоду, перерисовывает экран и снова засыпает.
  Время сна считается не «через 3 часа», а до ближайшего слота 00:05 / 03:05 / …,
  поэтому дата меняется сразу после полуночи.
- **Wi-Fi подключается с повторами**: если роутер ответил `AUTH_FAIL` или не
  успел, плата пробует снова каждые 20 секунд, пока бодрствует. Без этого
  один неудачный заход при старте оставлял устройство без сети до следующего
  пробуждения — а если пользователь жал кнопки, то и вовсе навсегда.
- Просыпаясь **кнопкой**, плата сначала рисует данные из RTC-памяти (погода и
  прогноз кэшируются в `RTC_DATA_ATTR`), и только если кэш старше 3 часов —
  идёт в сеть. То есть реакция на кнопку почти мгновенная.
- Пока плата спит, **USB-порт исчезает** — это нормально, а не поломка.
- Экран во сне **не гаснет**: линии панели (`RST`, `CS`, `DC`, `SCLK`, `MOSI`)
  прижимаются через `gpio_deep_sleep_hold_en()` перед сном. Без этого `RST`
  уплывал в низ, ST7305 сбрасывался и изображение пропадало — проверено на железе.
- Дата может отставать максимум на 3 часа (обновится на ближайшем пробуждении).

### Как прошить спящую плату

Порт отсутствует, пока плата спит. Порядок:

1. Нажать **KEY** или **BOOT** — плата проснётся и будет активна 2 минуты.
2. В течение этого времени запустить `python -m platformio run -t upload`.

Если подключить монитор порта или отправить любой символ в консоль, прошивка
**отключает сон до перезагрузки** — удобно при отладке.

Есть скрипт, который ждёт появления порта и сразу прошивает:

```powershell
powershell -ExecutionPolicy Bypass -File tools/wait_and_flash.ps1 -Port COM11
```

## Сетевой API (задел под внешний сервер)

Плата поднимает HTTP-сервер на 80 порту и mDNS-имя `rlcd-clock.local`.
Всё живёт в `src/services.cpp`; сюда же добавляются MQTT или нативный ESPHome API.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/status` | JSON: погода, дом, батарея, RSSI, uptime, время следующего подъёма, флаг сна |
| GET | `/forecast` | JSON: три дня (день, месяц, weekday, tmin/tmax, код и текстовое состояние) |
| POST | `/refresh` | Принудительно обновить погоду, отвечает сразу |
| POST | `/sleep?on=0\|1` | Запретить/разрешить глубокий сон (флаг хранится в NVS) |
| POST | `/test?partial=1` | Перерисовать экран полосами — самопроверка частичного обновления |

Пример:

```
$ curl http://rlcd-clock.local/status
{"device":"rlcd-clock","ip":"192.0.2.10","rssi":-63,"uptime_s":14,
 "next_wake_s":7789,"sleep_enabled":true,"weather_at":1794999302,
 "weather":{"valid":true,"temp":-1.5,"feels":-6.1,"wind":3.9,"humidity":70,
            "pressure":1018,"code":73,"state":"snow","tmin":-2.1,"tmax":-0.8},
 "indoor":{"valid":true,"temp":24.3,"rh":43},
 "battery":{"valid":true,"volt":4.14,"pct":100}}

$ curl -X POST "http://rlcd-clock.local/sleep?on=0"
{"sleep_enabled":false}
```

Практический смысл: сервер может на время обслуживания **удержать плату
активной** (`/sleep?on=0`) и вернуть обычный режим afterward. Любой запрос
к API продлевает окно бодрствования на 2 минуты.

Коды состояния погоды — WMO, те же, что мы используем для иконок
(`clear`, `cloudy`, `snow`, `rain`, `thunderstorm`, …).

### OTA по Wi-Fi

Кроме HTTP, на 3232 порту работает ArduinoOTA (имя `rlcd-clock`).
Проверено на железе: прошивка заливается по воздуху за ~35 секунд.

Плата должна бодрствовать. Проще всего скриптом, который дождётся её в сети
и сразу зашьёт:

```powershell
powershell -ExecutionPolicy Bypass -File tools/wait_and_ota.ps1 -Device rlcd-clock.local
```

Запустить, нажать **KEY** — дальше само. Либо вручную:

```powershell
$env:PLATFORMIO_UPLOAD_PROTOCOL="espota"
$env:PLATFORMIO_UPLOAD_PORT="rlcd-clock.local"
python -m platformio run -t upload
```

Пока идёт обновление, сон блокируется автоматически.

> Не обрезайте вывод `pio` через `Select-Object -First N` — PowerShell закрывает
> пайп и убивает загрузку на середине. Именно так OTA один раз «упал» без причины.
> Выводите в файл: `... | Out-File ota.log`.

> API без аутентификации — только для доверенной локальной сети. Пароль на OTA
> задаётся через `OTA_PASSWORD` в `config.h`.

## Быстрый старт

Два файла с личными данными в репозиторий не входят — они создаются из шаблонов:

```powershell
cp include/secrets.example.h  include/secrets.h     # Wi-Fi
cp include/location.example.h include/location.h    # город, координаты, часовой пояс
```

Заполнить оба (что именно — в таблице ниже) и прошить:

```powershell
$env:PYTHONUTF8="1"      # Windows: иначе PlatformIO падает на прогрессе в cp1251
python -m platformio run -t upload
```

Если файлов нет, сборка остановится с внятной ошибкой, а не соберётся молча.

## Что нужно задать

| Файл | Поле | Зачем | Пример |
|---|---|---|---|
| `include/secrets.h` | `WIFI_SSID` | имя сети, **только 2.4 ГГц** | `"home_2g"` |
| | `WIFI_PASS` | пароль WPA2 | `"••••••••"` |
| `include/location.h` | `CITY_NAME` | подпись города на экране | `"Москва"` |
| | `CITY_LAT` | широта для met.no | `"55.7558"` |
| | `CITY_LON` | долгота для met.no | `"37.6173"` |
| | `TZ_OFFSET_SEC` | смещение от UTC **в секундах** | `3 * 3600` |
| `include/config.h` | `MDNS_HOSTNAME` | имя платы в локальной сети | `"rlcd-clock"` |
| | `OTA_PASSWORD` | пароль OTA, пустая строка — без пароля | `""` |
| | `ENABLE_SERVICES` | HTTP-сервер и OTA: `1` вкл, `0` выкл | `1` |
| | `SLEEP_INTERVAL_S` | период пробуждения | `3 * 60 * 60` |
| `platformio.ini` | `upload_port` | **не задан** — порт ищется сам; укажи, если портов несколько | `COM5` |

Про координаты: подойдут любые с карты (Google/Яндекс), точность до 3–4 знаков
достаточна. Часовой пояс задаётся числом секунд, а не строкой POSIX TZ —
почему так, рассказано в разделе «Грабли». Примеры: Калининград `2*3600`,
Москва `3*3600`, Екатеринбург `5*3600`, Владивосток `10*3600`.

Сеть должна быть **2.4 ГГц**: ESP32-S3 не видит 5 ГГц. Если роутер раздаёт одну
SSID для обоих диапазонов, лучше завести отдельную гостевую сеть 2.4 ГГц.

## Сборка и прошивка

```powershell
$env:PYTHONUTF8="1"
python -m platformio run -t upload          # порт определится сам
python -m platformio run -t upload --upload-port COM5   # если портов несколько
```

Логи:

```powershell
python tools/logs.py COM11 20
```

> **Про путь проекта.** Линкер xtensa не умеет писать map-файл, если в пути есть
> кириллица или пробелы. В этом случае раскомментируй в `platformio.ini`
> блок `[platformio] build_dir = C:/pio-build/rlcd-clock` (путь — ASCII).
> На обычных путях ничего настраивать не нужно.

## Снимок экрана

Прошивка по команде `s` выводит кадр в hex, скрипт собирает PNG:

```powershell
python tools/shot.py COM11 preview.png       # главный экран
python tools/shot.py COM11 forecast.png f    # прогноз на 3 дня
python tools/shot.py COM11 status.png t      # экран состояния
```

Третий аргумент — команда перед снимком: `f` — прогноз, `t` — состояние, `i` — инверсия.
Учтите: дамп отдаёт *логический* кадр, поэтому инверсия на снимке не видна —
она применяется при отправке в панель.

Отладочные команды в консоли: `s` — дамп кадра, `f` — прогноз, `t` — состояние, `i` — инверсия.

## Грабли, которые уже собраны

**1. SCL и SDA перепутаны местами.** В BSP Waveshare конструктор —
`I2cMasterBus(scl_pin, sda_pin, port)` и вызывается как `(14,13,0)`.
То есть на этой плате **SCL = GPIO14, SDA = GPIO13**, а не наоборот.
Симптом: и RTC, и SHTC3 молчат одновременно.

**1a. DC и CS тоже перепутаны.** Конструктор `DisplayPort(mosi, scl, dc, cs, rst, …)`
вызывается как `(12, 11, 5, 40, 41, …)`, то есть **DC = GPIO5, CS = GPIO40**.
Если поменять их местами (как сделал я по аналогии с типовыми платами), панель
не получает данных и экран остаётся чёрным. Причём дамп кадра через Serial при
этом рисуется нормально — он не зависит от SPI и потому ничего не доказывает.

**2. Open-Meteo недоступен.** `api.open-meteo.com` (157.90.83.168) у ряда
провайдеров РФ не отвечает ни на 80, ни на 443 — TCP-таймаут, не TLS.
Поэтому используется `api.met.no`; проверить свою сеть можно
`python tools/netcheck.py`.

**3. Строка POSIX TZ ломает RTC.** С `TZ="<+05>-5"` newlib в ESP-IDF
трактует `mktime()` и `localtime()` несогласованно, из-за чего в RTC
записывалась произвольная дата (наблюдалось `2026-01-04` вместо `2026-11-18`).
Решение: фиксированное смещение `TZ_OFFSET_SEC` и `gmtime_r()` по
сдвинутому времени, без обращения к TZ-базе.

**4. NTP «синхронизировался» мгновенно.** Если перед синхронизацией
засеять системные часы из RTC, проверка `time() > 2023` проходит сразу.
Правильно — ждать `sntp_get_sync_status() == SNTP_SYNC_STATUS_COMPLETED`.

**5. Кириллица в пути.** См. `build_dir` выше.

**6. PowerShell 5.1 и UTF-8.** `Get-Content | Set-Content` перекодирует
файл в cp1251 и убивает кириллицу в исходниках. Правьте файлы редактором,
а не через пайплайн PowerShell.

## Особенности реализации

- Панель монохромная (1 бит), кадр упаковывается под нестандартный формат
  ST7305: `index = (x/2)*75 + (299-y)/4`, бит 7 — левый пиксель
- Шрифты генерируются из системных TTF в `include/fonts.h`
  (`python tools/gen_fonts.py`); готовый файл лежит в репозитории, чтобы
  проект собирался без Python и без набора шрифтов Windows
- Полный кадр — 15 000 байт, отправляется кусками по 2048 байт при 10 МГц
- **Частичное обновление**: экран разбит на 6 зон, UI помнит, какие строки
  реально нарисованы, и перерисовывает зону только при изменении текста.
  Отправляются только изменившиеся вертикальные полосы (см. раздел ниже)
- Часового таймера нет: экран трогаем только при смене даты или данных

## Частичное обновление экрана

Панель ST7305 адресуется по столбцам, и это неочевидно. `0x2B` — не строки
экрана, а **номера пар** `x/2` (0..199), а `0x2A` всегда полный (25 адресов).
Поэтому обновлять можно только вертикальную полосу на всю высоту, зато она
передаётся непрерывным куском кадра:

```
offset = (x1 / 2) * 75
len    = ((x2 - x1) / 2 + 1) * 75
0x2A = 0x12 .. 0x2A          (всегда)
0x2B = x1/2 .. x2/2
```

Зоны главного экрана разнесены по X, чтобы меняться независимо:

| Зона | Что | Ширина |
|---|---|---|
| дата | «СР, 18 ноября» | 180 px |
| температура | крупная цифра + «ощущ.» | 220 px |
| иконка | символ погоды + подпись | 110 px |
| детали | ветер/влажность, давление/мин-макс | 260 px |
| в доме | SHTC3 | 200 px |
| батарея | проценты + иконка | 114 px |

Экономия: полный кадр — 15 000 байт, обновление только индикатора «в доме» —
7 500, только батареи — 4 275. Пересекающиеся диапазоны сливаются в минимум
полос. В лог пишется `[flush] полос N, X из 15000 байт`.

Проверить, что полосы не ломают картинку, можно без Serial:
`curl -X POST "http://rlcd-clock.local/test?partial=1"` — все зоны
перерисуются полосами, изображение должно остаться прежним.
- TLS-сертификат не проверяется (`setInsecure()`): уходят только координаты,
  приходит публичный прогноз
- «Ощущается» считается по формуле wind chill (в compact-формате met.no
  готового значения нет)

## Если что-то не так

| Симптом | Что проверить |
|---|---|
| Плата не определяется, нет COM-порта | Она спит. Нажать **KEY** или **BOOT** и успеть запустить загрузку за 2 минуты |
| Экран белый/чёрный | питание, `PIN_LCD_*` в `config.h`, скорость SPI |
| Мусор на экране | порядок упаковки в `panel::flush` |
| «НЕТ WI-FI» | `include/secrets.h`, сеть 2.4 ГГц, WPA2 |
| Время `--:--` | NTP блокируется, смотрите строки `[ntp]` в логах |
| «погода недоступна» | `python tools/netcheck.py`, строки `[weather]` |
| Время уехало на другую дату | RTC испорчен старой прошивкой: дождитесь NTP-синхронизации, она перезапишет чип |
